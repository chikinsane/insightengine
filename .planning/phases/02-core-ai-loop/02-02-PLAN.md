1. Create `insightengine/src/lib/query/query-validator.ts`:
- Export `validateSQL(query: string): ValidationResult`
- Two-layer check: (a) regex `FORBIDDEN_DML` matching `\b(DROP|DELETE|INSERT|UPDATE|CREATE|ALTER|TRUNCATE|GRANT|REVOKE|EXEC|EXECUTE)\b` case-insensitive, (b) regex `REQUIRE_SELECT` matching `^\s*(WITH\s+.+?\s+)?SELECT\s` case-insensitive dotall
- Empty/whitespace-only strings return `{ valid: false, reason: 'Query must be a SELECT statement.' }`
- Also export `validateColumnReferences(sql: string, validColumns: string[]): ValidationResult` — extracts column-like identifiers from SQL and checks each against the validColumns list. Returns `{ valid: false, reason: 'Unknown columns: [list]. Valid columns are: [list].' }` on mismatch.

2. Create `insightengine/src/lib/query/duckdb-client.ts`:
- Export `executeQueryOnFile(fileBuffer: Buffer, sql: string, datasetId: string, fileType: 'csv' | 'xlsx'): Promise<QueryResult>`
- Writes buffer to `/tmp/${datasetId}.${ext}` (csv or xlsx)
- Creates DuckDB in-memory instance via `DuckDBInstance.create(':memory:')`
- For CSV: `CREATE TABLE data AS SELECT * FROM read_csv_auto('/tmp/...')`
- For XLSX: convert to CSV first using SheetJS, then same DuckDB load
- Execute the SQL (table name is always "data")
- Use `connection.runAndReadAll()` to get results
- Format into QueryResult with columns metadata and row objects
- ALWAYS clean up: `connection.close()`, `instance.close()`, `fs.unlinkSync(tmpPath)` in finally block

3. Create `insightengine/src/lib/query/result-formatter.ts`:
- Export `formatResult(rawColumns: string[], rawRows: unknown[][]): QueryResult`
- Export `buildStatSummary(result: QueryResult): string` — for each column (capped at 20): if numeric values exist, compute min/max/mean/count; if string values, list top-10 unique values + unique count. Return as newline-separated string.
- Cap summary at 20 columns; append "and N additional columns" if more exist.

4. Write tests FIRST for query-validator (red phase), then implement. DuckDB client does not need unit tests (integration tested in Plan 04).

1. Create `insightengine/src/lib/ai/anthropic-client.ts`:
- Export `getAnthropicClient(): Anthropic` — singleton pattern, creates one `new Anthropic()` instance (reads ANTHROPIC_API_KEY from env automatically).

2. Create `insightengine/src/lib/ai/prompts.ts`:
- Export `NL_TO_SQL_SYSTEM_PROMPT` — system prompt instructing Claude to generate DuckDB-dialect SELECT-only SQL, table name is always "data", column references must exactly match schema.
- Export `buildSchemaContext(columns: SchemaColumn[], rowCount: number): string` — XML-tagged schema string: `<schema>Table: data (N rows)\nColumns:\n  - colName (type) -- samples: val1, val2, val3\n</schema>`
- Export `INSIGHT_SYSTEM_PROMPT` — instructs Claude to write 1-2 sentence plain English insight from statistical summary, focus on the key finding.
- Export `FOLLOWUP_SYSTEM_PROMPT` — instructs Claude to generate exactly 3 follow-up questions based on the dataset schema and current query result summary.

3. Create `insightengine/src/lib/ai/nl-to-sql.ts`:
- Export `generateSQL(question: string, columns: SchemaColumn[], rowCount: number, previousError?: string): Promise<{ sql: string; explanation: string }>`:
  - Uses `getAnthropicClient().messages.parse()` with `zodOutputFormat` from `@anthropic-ai/sdk/helpers/zod`
  - Zod schema: `z.object({ sql: z.string(), explanation: z.string(), confidence: z.enum(['high','medium','low']) })`
  - Model: `claude-sonnet-4-5-20250929`
  - On previousError, append correction context with valid column list
- Export `executeWithRetry(question: string, columns: SchemaColumn[], rowCount: number, fileBuffer: Buffer, datasetId: string, fileType: 'csv' | 'xlsx'): Promise<{ sql: string; explanation: string; result: QueryResult }>`:
  - Loop up to 3 attempts
  - Each attempt: generateSQL -> validateSQL -> validateColumnReferences -> executeQueryOnFile
  - On DML validation failure: retry with reason "Query rejected: [reason]"
  - On column validation failure: retry with reason listing valid columns
  - On DuckDB execution error: retry with error message + valid column list
  - After 3 failures: throw `Error('Could not generate a valid query after 3 attempts')`

4. Create `insightengine/src/lib/ai/enrichment.ts`:
- Export `generateInsight(statSummary: string, question: string): Promise<string>` — calls Claude Haiku with INSIGHT_SYSTEM_PROMPT, passes stat summary (NOT raw rows), returns 1-2 sentence insight.
- Export `selectVizType(result: QueryResult, question: string): Promise<VizType>` — calls Claude Haiku, returns suggested VizType.
- Export `applyVizGuardrails(suggestedType: VizType, result: QueryResult): VizType` — rule-based overrides:
  - 1 datetime + 1 numeric column -> "line"
  - Category with >8 unique values -> "table"
  - 2 numeric columns (no category) -> "scatter"
  - Values sum to ~100 or ~1.0 -> "pie"
  - <8 categories + numeric -> "bar"
  - Default/fallback -> "table"
- Export `generateFollowUps(statSummary: string, question: string): Promise<string[]>` — calls Claude Haiku, returns exactly 3 follow-up question strings.
- Export `runParallelEnrichment(result: QueryResult, question: string): Promise<EnrichmentResult>` — runs `Promise.allSettled([generateInsight, selectVizType, generateFollowUps])`, applies vizGuardrails, returns EnrichmentResult with graceful fallbacks on failure.

5. Tests use vi.mock to mock the Anthropic client. The mock returns controlled structured outputs. Tests verify:

   - Retry loop increments attempt count and includes error in correction prompt
   - Enrichment sends stat summary (not raw rows)
   - VizGuardrails override LLM suggestions based on data shape rules
   - Follow-ups mock returns array of 3 strings
